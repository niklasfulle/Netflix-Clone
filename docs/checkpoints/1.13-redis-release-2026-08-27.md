# 1.13 Redis resilience and release checkpoint — 2026-08-27

## Scope and durable decisions

- GitHub issues #54 through #62 are complete; #63 is the active release gate.
- Redis remains isolated, environment-scoped, TTL-bound, and non-durable.
- PostgreSQL remains authoritative for authentication throttling, accepted job
  runs, lifecycle transitions, worker heartbeat evidence, audits, and business
  records.
- An unavailable or disabled Redis runtime uses the documented PostgreSQL
  fallback or an explicit degraded/unavailable response. It is never reported
  as healthy.
- Production promotion must use the exact application and Redis image digests
  exercised on staging.

## Implemented verification

- `yarn test:redis-resilience` consolidates cache/fallback parity, authentication
  authority, coordination, duplicate delivery, retries, cancellation, dead
  letters, stale leases, heartbeat, retention, and worker-drain tests.
- `yarn test:redis-resilience --with-docker` adds real Redis timeout, circuit,
  reconnect, restart, memory-pressure eviction, ACL, environment-isolation, and
  ephemeral-data drills.
- The operations runbook defines capacity signals, safe disablement, worker
  crash/recovery, rollback with queued work, debugging, and secret-redaction.
